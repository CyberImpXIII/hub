**5.10 Jacob's answers on Decisions 1–4 and §5.5–5.7 (planner window, 2026-10-09).**
- **D1, warm roles: Jacob, "I thought we determined this wasn't necessary, especially
  so with the context cleaner we are building, but specifically because the 29k
  happens either way."** He is right, and 5.8's "so it doesn't pay the ~29k-token
  start each time" was wrong. Claude Code "re-sends the full context: the system
  prompt, your project context, every prior message and tool result" on every request,
  and the API caches "by matching the start of each request ... against content it
  recently processed" (prompt-caching#how-the-cache-is-organized). So the ~29k prefix
  is sent on every message, warm or cold, and read from cache either way while it is
  recent; a warm role saves no start, and adds a history that grows with each message,
  the thing context-hygiene exists to cut. Routing-tree §11 already said "cold roles
  first; warm roles only where the token numbers show a saving". Proposed: drop warm
